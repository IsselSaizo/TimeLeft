# Time Left — план переделки

> Бывший DeathClock / LTimeClock (Unity). Переписываем с нуля в этом же репозитории;
> старая версия остаётся в истории под тегом `v1.0-unity`.

## 1. Концепция

Часы «как в фильме In Time»: обратный отсчёт оставшейся жизни в зелёной «светящейся» стилистике.
Привычки за день сдвигают отсчёт («+12 мин», «−35 мин»).

### Формат отображения
- **Годы и дни — цифрами** (крупно): `47 лет 213 дней`.
- **Часы, минуты, секунды — аналоговым циферблатом**: стрелки показывают остаток
  текущих суток (ЧЧ:ММ:СС до следующего «минус дня»), идут против часовой стрелки.
- Годы/дни считаются по календарю (с високосными годами), а не «365 дней».
Позиционирование — **мотивация/развлечение, не медицина**. Всё локально, без сервера.

### Главный принцип: храним момент, а не тикаем

- Храним одну величину `end_at` (UTC, мс) — оценку момента, к которому идёт отсчёт.
- Остаток = `end_at − now`. Ничего не тикает и не сохраняется каждую секунду, время идёт при закрытом приложении.
- Любое изменение (анкета, привычки, ежедневная перекалибровка) — запись в **журнале** (`ledger`):
  `{ts, delta_ms, reason, breakdown}`. Журнал объясняет, откуда взялся каждый сдвиг.
- Часы получают только `end_at` (+ версию журнала) и рисуют отсчёт системными средствами:
  Wear OS `TimeDifferenceComplicationText`, watchOS `Text(timerInterval:)` в WidgetKit.

## 2. Выбор стека

### Рассмотренные варианты (статус на ноябрь 2026)

| Вариант | Телефоны | Часы | Вердикт |
|---|---|---|---|
| **Rust-ядро + UniFFI + нативный UI** (uniffi 0.32, cargo-ndk, cargo-swift) | Kotlin/Compose, SwiftUI | нативно | ✅ **выбран** |
| Crux (Rust, Elm-архитектура, нативные оболочки) | нативно | не документировано | ❌ pre-1.0, сменил FFI на BoltFFI, слишком тяжёлый для маленького приложения |
| Slint / Dioxus / Tauri 2 / egui / Makepad (весь UI на Rust) | да | **нет** (ни complications, ни tiles, ни WidgetKit) | ❌ для часов всё равно нужен натив, интерфейсы разъедутся |
| Kotlin Multiplatform + Compose MP | да (iOS стабилен) | Wear — да; watchOS — только ядро (Beta), UI на SwiftUI | ⚖️ сильная альтернатива, если Rust не принципиален |
| Flutter (+ flutter_rust_bridge) | да | официальной поддержки нет | ❌ |

### Решение

- **Rust-ядро только на телефонах.** Часы — тонкие нативные приложения без Rust:
  - Rust для watchOS: `aarch64-apple-watchos` — Tier 2 (с Rust 1.95), но `arm64_32` (старые Apple Watch) — Tier 3, нужен nightly. Обходим это стороной;
  - на часах не нужны `.so` и JNA, меньше размер и расход батареи;
  - логики на часах почти нет: показать `end_at`, отправить отметку привычки на телефон.
- Корректность ядра на всех платформах подтверждают общие **тестовые векторы** (`testdata/vectors/*.json`).

## 3. Модель расчёта

### 3.1 Данные
- **UN World Population Prospects 2024**, полные таблицы смертности (однолетние возрасты 0–100+, M/F,
  1950–2023 + прогноз 2024–2100), лицензия **CC BY 3.0 IGO** — можно встраивать с атрибуцией
  «© United Nations, WPP 2024». Ни WHO GHO (NC), ни HMD (мало стран) не подходят.
- Офлайн-утилита `tools/lifetable-builder` скачивает CSV (~200 МБ gz каждый, потоковое чтение) и собирает
  компактный `lifetable.bin`: `mx` за 2024 год + годовой темп улучшения `r_x` по возрастам
  (из прогноза 2024→2050) для ~237 территорий × 2 пола × 101 возраст. ≈0,3 МБ после zstd.

### 3.2 Метод
1. Базовая смертность по стране/полу; **когортный** подход: для возраста `a+t` берём `mx·(1−r_x)^t`
   (периодные таблицы занижают остаток у молодых).
2. После 100 лет — экстраполяция Гомпертца (подгонка по 80–99), обрыв на 120.
3. Факторы риска — пропорциональные риски: `q' = 1 − (1 − q)^HR`.
   - **Ослабление с возрастом:** `ln HR(a) = ln HR · w(a)`, `w = 1` до 50 лет → 0.5 к 90 годам.
   - **Комбинирование:** `ln HR_tot = Σ ln HR_болезни + 0.75 · Σ ln HR_образ_жизни`, затем clamp `[0.5; 5]`
     (образ жизни коррелирует, простое перемножение даёт двойной учёт).
4. Выход — **распределение**, а не одно число: функция выживания `S(t)`, медиана (S = 0.5),
   квартили (S = 0.75 / 0.25), среднее. Отсчёт идёт к **медиане**; в UI подпись
   «половина людей с похожим профилем живёт дольше; типичный диапазон Q1–Q3».
5. Раз в сутки пересчёт `e(a)` (с возрастом условный остаток убывает медленнее 1 года/год);
   разница — отдельная запись журнала «перекалибровка».

### 3.3 Черновая таблица факторов (уточнится в `docs/methodology.md`)

| Фактор | Уровни → HR | Источник |
|---|---|---|
| Курение | никогда 1.0; курит M 2.8 / Ж 3.0; бросил: `1 + (HR−1)·g`, g = 0.1 (<40), 0.4 (40–54), 0.6 (55+) | Jha 2013 NEJM |
| Активность (MVPA мин/нед) | 0 → 1.0; 1–149 → 0.80; 150–299 → 0.69; 300–449 → 0.63; 450+ → 0.61 | Arem 2015 JAMA IM |
| *или* шаги/день | ~3.5k 1.0; ~5.8k 0.60; ~7.8k 0.55; ~10.9k 0.47 (плато) | Paluch 2022 Lancet PH |
| ИМТ | <18.5 1.51; 18.5–20 1.13; 20–25 1.0; 25–27.5 1.07; 27.5–30 1.20; 30–35 1.45; 35–40 1.94; 40+ 2.76 | GBMC 2016 Lancet |
| Алкоголь (г/нед) | 0–100 1.0; 100–200 / 200–350 / >350 → калибровка под −0.5 / −1…2 / −4…5 лет e(40) | Wood 2018 Lancet |
| Сон | 7–8 ч 1.0; короткий 1.12; долгий ~1.1 (ограничено, маркер болезни) | Cappuccio 2010 Sleep |
| Социальные связи | слабые ~1.3 | Holt-Lunstad 2010 (консервативно) |
| Диабет / инсульт / инфаркт | 1.9 / 2.1 / 2.0 (перемножаются) | ERFC 2015 JAMA |
| Питание | ~0.8 топ vs низ | ⚠️ нужен проверенный источник |

### 3.4 Ежедневные привычки (без бесконечной «накачки» времени)
- По каждой поведенческой привычке храним скользящее среднее за ~90 дней:
  `E ← E + (x_day − E) / 90`.
- `E` → HR фактора → новый `e(a)`; дневной сдвиг `Δ = e(E_new) − e(E_old)` пишется в журнал.
- Сумма сдвигов ограничена разницей «хороший профиль − плохой профиль»: годы не накачать, один срыв не обнуляет прогресс.
- Проверка на здравый смысл: курение ≈ −10 лет из ~50 → ≈4.8 ч/день ≈ 14 мин/сигарета при пачке в день —
  тот же порядок, что «≈20 минут за сигарету» (Jackson et al., Addiction 2025).
- Отметка — раз в сутки (вечером), повторное нажатие отменяет; список привычек настраиваемый.

### 3.5 Этика и магазины
- Не показываем «дату смерти» — показываем отсчёт к медиане + диапазон; режим «скрыть счётчик».
- Тон ободряющий («вы вернули 2 часа»), без стыда за срывы; мягкие формулировки при болезнях/старшем возрасте.
- Методология и источники — прямо в приложении; «оценка по популяционным данным, ассоциации, не причинность».
- Дисклеймер «не медицинское изделие, не диагностирует…», совет обращаться к врачу; 18+.
- Apple Guideline 1.4.1; Google Play Health apps declaration + политика конфиденциальности.
- Данные о здоровье только на устройстве.
